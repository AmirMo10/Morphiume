# داده و تاریخچهٔ پایدار

فایل‌های SQL در `db/migrations` منبع constraint و schema هستند؛ checksum مهاجرت اعمال‌شده نگه‌داری می‌شود و فایل قبلی بی‌خبر قابل بازنویسی نیست. `db/schema.ts` نگاشت مدل‌های احراز هویت BetterAuth را دارد. مهاجرت‌ها با نقش owner و اجرای عادی با نقش محدود DML انجام می‌شوند.

کاربر/نشست/OTP/نقش، محصول/تنوع/رسانه/مجموعه، موجودی/رزرو/دفتر انبار، سبد/نشانی/علاقه‌مندی، سفارش و snapshot اقلام، تلاش/دریافت/رخداد پرداخت، ارسال/مرجوعی/بازپرداخت، کوپن/سهم مصرف، محتوا/تنظیمات و outbox/audit مدل شده‌اند. مبلغ و وضعیت مالی از وضعیت ارسال مستقل‌اند؛ پاک‌کردن یا تغییر محصول تاریخچهٔ سفارش را تغییر نمی‌دهد.

شرح رابطه‌ها، state transitionها و guardها در [مدل دادهٔ بک‌اند](backend/DATA_MODEL.md) و [قواعد اتمیک](backend/INVARIANTS.md) نگه‌داری می‌شود. جدول `bulk_operation` نتیجهٔ اصلاح گروهی و fingerprint درخواست را برای replay معتبر حفظ می‌کند؛ پیش‌نمایش هیچ اثر مالی/موجودی ندارد. زمان‌های رخداد UTC و نمایش تاریخ شمسی با منطقهٔ تهران است.
