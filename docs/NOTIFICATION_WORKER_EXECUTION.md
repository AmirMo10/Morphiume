# اجرای واقعی job اعلانِ متعلق به fixture

این اجرای کنترل‌شده فقط پایگاه تازهٔ `morphiume_staging_qa_b625408702be90db` و یک schema موقت تولیدشده را هدف گرفت. اعتبار migration-owner فقط به فرایند جداگانهٔ fixture داده شد؛ برنامهٔ وب آن را نداشت. fixture از کارخانهٔ واقعی job و dispatcher واقعی استفاده کرد، با انتخاب محدود یک job و بدون مصرف صف مالی یا jobهای عمومی نامرتبط. این پذیرش حلقهٔ کامل worker داخل تصویر یا احراز هویت بومی نیست.

## نتیجهٔ واقعی

برای source fixture با SHA256 `60010091d2bce5cd7563f5632b0c8d90fc575b322adef88a49028745b971073c`، capture در `2026-10-13T02:58:07.622Z` آغاز شد. تابع fixture در **11751ms** تمام assertionها و cleanupِ awaitشده را گذراند و گزارش بازگرداند:

- یک `notification.event` متعلق پردازش شد و رخدادهای worker برابر started/completed بودند.
- دو پیام، یکی برای مشتری و دیگری برای اپراتور واجد شرایط، ساخته شدند؛ دلیل خام و اطلاعات خصوصی fixture وارد متن نشد.
- replay صفر پیام تازه ساخت و دو وضعیت خواندن محفوظ ماند.
- jobهای دیگر در schema متعلق و وضعیت مالی همان سفارش تغییر نکردند؛ tick بعدی job دیگری پردازش نکرد.
- `nativeAuthenticationProved=false`: actor/sessionهای این fixture کنترل‌شدهٔ دامنه‌اند و جای MFA/OTP بومی را نمی‌گیرند.

مشاهدهٔ فقط‌خواندنی مستقل در `03:04:31.617Z` تعداد ۵۳ جدول public، تاریخچهٔ ۱۳ مهاجرت، صفر schema موقت باقی‌مانده و نقش DML بدون CREATE را تأیید کرد. برابری تمام ردیف‌های public اندازه‌گیری نشد. مرجع پایگاه اصلی یا سرویس runtime613 از این نتیجه به دست نمی‌آید.

## شکست‌های محفوظ و بازیابی گزارش

نخستین اجرا پیش از ورود به fixture با خطای transform شکست خورد: `top-level await` با خروجی CommonJS loader این پروژه سازگار نبود. footer به Promise با catch ثابت تغییر کرد؛ حالت فاقد GO با loader عادی واقعاً به انکار ثابت و بدون ورود به شاخهٔ PG رسید. رفتار تجاری، assertionها و cleanup تغییر نکردند.

اجرای دوم تابع را موفق تمام کرد، اما فرایند capture با exit1 پایان یافت: خروجی مهاجرت‌های schema موقت پیش از JSON بود و reader کل لاگ را یک JSON فرض کرده بود. این نقص خواندن گزارش، شکست assertion تجاری معرفی نمی‌شود. در `03:03:54.272Z` فقط همان capture خصوصی خوانده شد؛ رد parser قبلی بازتولید، دقیقاً یک summary با scope و کلیدهای مجاز اعتبارسنجی و شواهد بازیابی شدند. **هیچ PG یا اجرای دوباره‌ای برای این بازیابی انجام نشد.** Parent exit1 و هر دو لاگ شکست محفوظ‌اند؛ exit0 برای parent ادعا نمی‌شود.

شناسهٔ اجرای دوم `864b8899-0eb3-4640-b943-502cda096c35` و SHA256 لاگ خصوصی آن `4fc8ac7085c74b5f94da53b66da91fb6821d3abcf498cac39bea945ed652a926` است. Reader خصوصی برای اجراهای بعدی اصلاح شده، ولی نتیجهٔ بالا از همان capture اولیه است. UI اعلان‌ها، مرورگرهای تازه، consumer داخل تصویر، اتصال به رخدادِ ساخته‌شده با نشست بومی و استقرار سازگار پذیرش‌های جداگانه‌اند.
