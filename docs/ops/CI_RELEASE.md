# CI and controlled release contract

The coordinator owns shared package scripts and `.github` workflow files. This is the operations interface and acceptance contract for their implementation; a workflow existing in source does not establish that a CI run passed.

Use the pinned Node runtime/package manager and frozen lockfile. Required jobs are install, lint, typecheck, meaningful domain/authorization/concurrency tests against disposable real PostgreSQL, production build, browser acceptance tests, dependency audit, secret scan, image vulnerability scan and artifact manifest. Record exact commit/tool versions and reports. Preserve failures as evidence; confirmed critical/high reachable findings and finance/inventory/authorization failures block release. Generate a dependency/asset license/provenance register and compatible SBOM/provenance alongside the immutable image.

Build `linux/amd64` off the deployment server from `deploy/staging/Dockerfile`; test that app/worker/migration all start as uid1001. Run release smoke/security/performance checks with `NODE_ENV=production`, `DEPLOYMENT_ENV=staging` and controlled mock adapters. Explicitly test live-mode rejection of mocks, missing secrets, seed/demo controls and unsafe config. Do not give unknown pull requests registry write or deployment/PSP/SMS secrets. Pin third-party Actions by reviewed full commit SHA; do not use unverified mutable tags for release identity.

Publishing an image or deployment artifact needs coordinator authorization. After an approved push/release, keep the last known-good image identity and compatible schema plan, verify transferred image checksum/digest, quietly validate Compose, back up, migrate once, wait for app/worker readiness and perform T25. Limit release concurrency so two migrations/deploys cannot overlap. Serialize deployment using a host lock or environment concurrency; do not expose the Docker API publicly. Use a dedicated constrained deployment identity before enabling unattended CI access; the current root SSH key is for the authorized manual setup and does not establish minimal CI privileges.

Retain build logs/test reports/image SBOM and source revision without runtime secrets or DB dumps. Retry with verified official package/image mirrors/caches during network failures, and document the cache completeness; incomplete caches cannot promise offline builds. Live release remains blocked by owner inputs, verified service connections, restore evidence, independent acceptance/security tests and actual network/capacity results in their reports.
