# Request correlation and private-data boundaries

Latest main application checkpoint is `fd749616a31706a1c177bb107bb07c8aa73f9643`: actual local22/22 production browser cases include malformed/oversized/cross-origin native-auth requests, private caching and server-issued correlation IDs. The next uncommitted diagnostic change adds only a fixed `failureCategory` to an INTERNAL request-completed record. Known plain PostgreSQL error codes map to database_deadlock, database_serialization, database_constraint, database_connection, database_schema or database_timeout; all other errors map to unexpected. Own value descriptors are inspected without invoking getters. Neither SQLSTATE itself nor message/name/detail/query/schema/constraint data is emitted; the public response stays the same generic500. This category does not prove the cause of the earlier CI500, which predates this change. Observability10+CSV3 unit cases passed13/13 in805ms with private error canaries; native/build acceptance of the new category remains pending.

The API wrapper generates a fresh UUID for each request and returns `X-Request-ID` on success, redirects and handled errors. Client-provided correlation headers are ignored. Node AsyncLocalStorage keeps the request context isolated across concurrent asynchronous work. Logs record only the server timestamp, static route category, HTTP method, status, elapsed milliseconds and an allowlisted error code. Unknown routes use `api.other`; full paths and query strings are never recorded.

Successful checkout/payment retry responses add the database-issued order and payment-attempt UUIDs. Authorized order/shipment reads and verified payment responses add their known order UUID. The logger accepts only UUID-shaped correlation identifiers and enumerated outcomes. It does not serialize request bodies, cookies, authorization, actor contact details, postal addresses, search text, OTP/TOTP, bank references, provider payloads or refund evidence. Correlation identifiers remain pseudonymous internal operational data, so server-log access and retention still require an operator policy.

`*.response` events describe responses, including idempotent replay. They are not deduplicated commerce analytics, sales totals, notifications or evidence of a new receipt. Database receipts, inventory ledgers and immutable order snapshots remain authoritative. Worker wiring now records durable lease/start/completed/retry/dead observations with job UUID, an allowlisted job type, bounded attempt number and named order/payment-attempt UUIDs when present. Arbitrary payload, provider reference, dedupe key and error text are excluded. The observer cannot alter the durable outcome; its actual PostgreSQL acceptance is recorded in the backend report. Actual server worker execution is still pending deployment.

The wrapper preserves response status/location, all cookie headers and private caching when adding the identifier. A log-sink failure cannot turn a committed operation into a failed response. All customer/admin authentication POST bodies are independently limited to128000bytes, including streamed bodies without Content-Length, before the maintained auth library receives them. Numeric phone/TOTP normalization requires a JSON object; malformed/null/array input receives a controlled validation response. Existing native MFA/OTP/rate rules are unchanged.
