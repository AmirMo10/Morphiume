# Authentication quota scope and safe errors

This next-source change is uncommitted and has not yet been exercised against a new production build or PostgreSQL-backed native fixture. It fixes a mechanism reproduced using the actual installed Better Auth1.7.7 hook dispatcher with its controlled memory adapter and a mocked exhausted app limiter. Original CI fd74961 collection500 and missing shipping response remain unattributed; see [the exact CI diagnosis](qa/CI_FD74961_DIAGNOSIS.md).

The admin before-hook previously charged every internal `adminAuth.api.getSession({headers})` call to `admin-auth:global`. A legitimate private catalog/session read was therefore counted as a public authentication request. The application limiter's APIError429 could escape a direct API call and the generic commerce HTTP wrapper returned INTERNAL500. Baseline native-hook tests had two failures and one passing real-HTTP limit case in2.01s; no PostgreSQL query or real credential/session was issued.

Only an internal `/get-session` call with no native Request is exempt from this authentication budget. Actual HTTP auth endpoints, including HTTP get-session, and direct authentication mutations retain the existing200/60 app guard. Maintained native600/60 and endpoint-specific rules, MFA, cookies and role permissions are unchanged. Body input cannot supply the framework's request context. Internal reads still validate the maintained session and the application's current account/MFA/role rules.

The fixed-window counter keeps its existing threshold and SQL. When exceeded, it returns a positive ceil of its remaining window in Retry-After; SMS500/hour stays separate. The ordinary HTTP wrapper maps native429 to a fixed Persian RATE_LIMITED429 and forwards only a valid numeric Retry-After1..3600. It never forwards arbitrary headers, error body/text, cookies or credentials and invents no missing interval. Native handler responses retain their original library behavior.

Current focused acceptance: auth scope3 + fixed-window budget4 + observability10 + CSV3 passed20/20 in3.90s. Native hook tests use the maintained real dispatcher/handler, controlled memory storage and limiter; budget tests mock SQL and local Date.now solely inside their unit process. They do not reset an operating rate-limit row, change the host clock or prove PostgreSQL/native-browser capacity. Independent valid-session HTTP/PG budget checks and the new full production acceptance are prepared by QA and still pending.

Primary behavior references: [Better Auth hooks and optional native request context](https://better-auth.com/docs/concepts/hooks), [direct server API and APIError behavior](https://better-auth.com/docs/concepts/api). Installed `dist/api/to-auth-endpoints.mjs` and dispatch source were inspected.
