The customer context installs `addInitScript`, a MutationObserver, passive input/change/click/focus/resume listeners and an independent BroadcastChannel listener. It never replaces a browser API, sends a privacy/session signal, dispatches an event, intercepts a native request or mutates the DOM. The existing channel's payload is reduced immediately to the fixed kind `session` or `privacy`; owner IDs, signal nonces and other properties are not retained. Native UI request/response/transport-abort chronology records only fixed route aliases and numeric HTTP status. Headers, queries, body, credentials and request identifiers are not read.

DOM records contain a fixed event kind, monotonic-derived wall timestamp, observer-only numeric node ID, fixed alias (`phone`, `code`, `send`, `verify`) and booleans for value presence, visible native-check status and paused/inert/hidden state. Values and label/text content are not stored. Page aliases are `buyer`, `peer`, `account` or `other`, assigned by controlled creation order. Unknown properties/enums, nonfinite numbers, inconsistent node IDs and primitive/null/array payloads are rejected.

Each document is capped at256 records with a final fixed `observer-cap` marker; the whole private log is capped at2048 events, with dropped/rejected counts. Observer IDs are capped at4096. Fresh documents restart their observer IDs; they are not application identities. Logs are written only under ignored `.local/qa-lifecycle/`, without attachments/traces or public raw dumps. The console emits only stored/count/drop/reject booleans/numbers. The finishing logger catches its own failure so it cannot interrupt fixture cleanup.

Limits: an extra channel listener and DOM traversal introduce observational work and can change timing. MutationObserver delivery is asynchronous and cannot prove uninterrupted visibility between records; the status boolean checks only the known native-check UI. APIRequestContext requests outside a page do not appear in browser network events; their existing native-status evidence remains separate. A page script could call the diagnostic binding, so records are observations, never an authorization proof. Cap markers/dropped counts mean later events may be absent. Actual cause requires a reproduced bounded native sequence; these guards alone establish no Chrome root cause.
