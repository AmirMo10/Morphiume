## Source-only native correction

`notification-owned-delivery.ts` is a guarded server-only child, invoked with the repository's normal `node --conditions=react-server --import tsx` loader. It receives only runtime DML configuration and bounded stdin containing the exact owned order/customer/operator relationship. It never reads an env file or migration-owner/auth/control credential. Input is capped4096bytes, operators1–3, own notification jobs2–24; the child has a20s parent lifetime bound, and pending handling a12s deadline. Connection/query bounds are3s/3.5s; these are engineering safeguards, not measured signup/delivery throughput or a cancellation guarantee.

The ordinary `createJobs` notification handler/claim/completion logic and real dispatcher remain in use. Only leasing is restricted to the selected order's exact canonical job IDs/type; reservation expiry is deliberately a no-op to prevent unrelated public sweeps. Pending/running/completed are recognized. Dead, unknown, mismatched payloads, retained delivery errors and privilege/ownership failures stay failures. Concurrently running legitimate own jobs can finish normally; there is no forced lease/status, backoff reset or broad retry. Already completed rows are preserved. The ordinary packaged worker remains enabled in CI.

Operator native fixtures initially enroll genuine MFA as owner so both streams can be canonically delivered. Only their exact owned memberships are then reduced to fulfillment/finance inside an audited `qa.fixture.notification_permission_reduced` preparation transaction. This is explicitly a membership fixture, not a claimed native role-edit workflow. The final real owner role API withdrawal and current-factor denial checks remain unchanged.

The browser spec checks exact own event/recipient IDs and canonical keys/templates. Every retained visible or read row is independently joined to its genuine source event/order and checked against current permission and the generic template. A bounded full current-permission DB model independently verifies global totals, order, unread counts and native DTOs; unknown, duplicate, omitted or private rows cannot be hidden by filtering. UI counters use that validated DTO, require an exact one-read decrement, and verify the real empty state when total0 or legitimate retained rows otherwise. Owner/customer identity, no-store, strict PATCH, foreign404, exact disabled403 versus revoked401, native MFA and financial assertions remain.

Current CI setup originally used its PostgreSQL bootstrap identity as both DATABASE_URL and MIGRATION_DATABASE_URL. The child intentionally rejects that privileged identity.
