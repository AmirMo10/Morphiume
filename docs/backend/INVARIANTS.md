# Commerce invariants

Observed/implemented contract, 2026-10-12. Runtime checks are reported separately; this document is not proof of passing tests.

- DB and server money use integer IRR; public JSON uses decimal strings. Prices, shipping and payable totals are whole تومان expressed as multiples of 10 IRR. Admin price input is an integer تومان string converted once. Application money cap is 1,000,000,000 IRR, an engineering limit rather than a provider promise. Percent discounts round down to whole تومان. Tax is zero in controlled staging until owner-approved applicability exists.
- `on_hand >= reserved >= 0`; sellable equals on_hand minus reserved. Cart creation reserves nothing. Checkout locks balances in UUID order, snapshots accepted amounts/recipient/policy, creates reservation, attempt and outbox in one transaction. Network calls occur after commit.
- `checkout_idempotency` is scoped to user and operation and checks a canonical request fingerprint. Different input with the same key conflicts; an existing operation returns its preserved result even after policy settings change. Cart secrets are opaque random values stored only as digests; claim rotates the digest and requires the verified customer thereafter. Object IDs alone grant no access.
- A successful receipt is unique by provider, merchant and provider reference. One order commits inventory once and has at most one shipment. Every distinct receipt remains recorded; additional funds enqueue an exception. Late payment after released reservation reallocates only available stock, otherwise records a paid inventory exception.
- Expiry and stock changes write inventory ledger operation keys. Per-customer row locks serialize the three-active-order reservation budget. Worker jobs use durable outbox leases and retry, including payment initialization committed with the attempt. Delivery may repeat; external recipients must use the provided dedupe key. No global exactly-once claim applies.
- Product edits check a version and retain order snapshots. Missing variants become inactive. Inventory adjustment cannot reduce on_hand below active reserved stock.
- Bulk preview has no durable effects. Commit checks all product versions and reserved balances, locks sorted products/variants/balances, and updates all selected rows or none. Price and stock permissions apply only to their requested fields. The actor/key/fingerprint record stores one result and audit operation; repeated requests cannot apply stock movement twice.
- Free shipping is configurable in integer IRR, applies inclusively after discounts, and is fingerprinted with the resulting quote fee. Unset threshold keeps the existing fee. No threshold or shipping policy is inferred from brand facts.
- Customer order reads require current session and ownership. Admin operations require a current session, unexpired MFA grant and current role permission. Supporting operators cannot refund or change roles by default.
- Refund budgets lock the receipt/order and include pending, processing and succeeded refunds. Recording a manual completion does not automatically restock a returned perfume. Quality review and approved return policy are needed.

Reversible decisions: Next.js/TypeScript modular monolith; Drizzle stable schema for library auth plus explicit reviewed SQL domain migrations and pg transactions; one warehouse; standard shipping with configurable fee; PostgreSQL outbox; configurable 15-minute reservation; test/staging mock provider. Retain PostgreSQL financial records when changing any of these choices.
